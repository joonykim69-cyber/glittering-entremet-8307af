# test/ — 회귀 안전망

```bash
npm test                 # 전부 실행 (+ 마지막에 시계 +400일 스윕 1회)
npm test quota           # 파일명에 'quota'가 들어간 것만
node test/quota.test.js  # 파일 하나만 직접
```

`npm test`는 스위트를 한 번 더 **시계만 +400일 돌려** 실행한다(`SKIP_TIME_SWEEP=1`로 끔).
잡는 것은 두 부류다 — ① 날짜를 하드코딩해 그 날이 지나면 조용히 무의미해지는 픽스처
② 시점 로직 자체의 결함. 이 스윕을 처음 돌렸을 때 `predict-daily`가 **마감이 6개월 지난
물건 2,370건을 전부 봉인 대상으로 통과**시키는 것을 잡았다(창 필터에 하한이 없었다).
개별 확인은 `TIME_SHIFT_DAYS=400 node -r test/_timeshift.js test/foo.test.js`.

의존성 0(Node 내장만), 네트워크 호출 0. `test/*.test.js`를 각각 **별도
프로세스**로 돌린다 — 이 테스트들은 `global.__FAKE_STORE__`/`global.fetch`를 갈아끼우므로
한 프로세스에서 이어 돌리면 앞 테스트의 전역이 뒤로 새어 들어가 없는 통과를 만든다.

## 이 테스트들이 지키는 것

프레임워크 관례가 아니라 **헌장 규율**을 지킨다. "동작하는가"보다 "우리가 하지 않기로 한 일을
정말 안 하는가"가 핵심이다.

| 파일 | 지키는 규율 |
|---|---|
| `predict-seal` | 봉인 **창 양방향**(마감 지난 물건 미봉인 — GR11)·**전수**(페이지 상한으로 유실 없음)·**불변**(재봉인 0)·**공식 불변**(mid/lo/hi 수치 대조)·상한 시 마감 임박 순 |
| `score-daily` | 전수 채점·이중 집계 0·레벨별 관측 |
| `calibration` | **보정이 증거로만 움직이는가** — 채점 0건이면 미동작·하루 1회·누적이 아닌 최근 창·**빗나감이 한쪽으로 쏠리면 넓히지 않고 편향으로 진단**(GR4) + 프로덕션 실측 재현 |
| `mkt-seal` | 시세 밴드 봉인 불변(시세가 급변해도 덮어쓰지 않음)·채점이 봉인값 미변경·재실행 이중집계 0 |
| `mkt-backtest` | GR11(as-of 이후 거래 미참조)·표본 부족 시 미산출 |
| `collect-rtms` | 커서 재개·빈 셀 미저장·재실행 no-op |
| `collect-history` | 증분 고정 키(블롭 무한 누적 방지)·재실행 누적 0 |
| `quota` | 대량 수집기가 사용자 화면 몫을 침범하지 않음·**반쪽 창을 남기지 않음**(커서 미전진) |
| `alerts` | 같은 물건·단계 재발송 0·키 없으면 보낸 척 안 함·수신거부 시 이메일 삭제·불필요 필드 미저장 |
| `hwp` | HWP/HWPX 추출, 암호 문서는 정직하게 실패 (fixture는 제3자 구현 생성 — `fixtures/README.md`) |
| `curation` | **랜딩에 올릴 물건을 우리 기준으로 고르는가** — 수요 분류 필터·낙찰률 배제(유찰은 폴백)·신탁 분리·차익은 보수 가정으로만·동산엔 차익 미표기·보장 어휘 금지 + 지역 코드 서버/클라 사본 일치 |
| `gbtree` / `backtest-v08` | 분위수 GBDT 수치 정확도·GR11(예측 피처에 win 없음) |
| `sim-live` | GR11 — 예측 함수에 미래(win)를 넣어도 무시함을 실증 |
| `market-est` / `rtms-svc` | 실응답 형태 fixture로 파싱(과거 `{item:"<원시XML>"}` 버그 재발 방지) |
| `news-dedup` | 재게재 보도 제거·다른 회차 보존 |
| `mdlite` / `faildiag` | 임의 HTML 주입 차단·유찰 신호 판정 |
| `sealed-surface` | **화면 숫자 = 채점받는 숫자** — 상세가 봉인 장부를 조회하고, 봉인 없으면 수치를 비움 + 예측 시점(leadDays) 분리 |
| `market-surface` | 검증된 시세 정합도가 화면에 노출됨(GR12) + **시세·낙찰가 두 축 분리** 문구 동반 |
| `decision-flow` | **화면이 질문의 순서인가** — Q1~Q4 배열·빈 질문 묶음 숨김·판단 준비도가 투자 조언이 아님(좋다/나쁘다·추천 어휘 금지)·근거 태그 분해·성적표는 표본 20건 미만이면 침묵 |
| `outcome` | **결과 예보도 봉인·채점된다** — 낙찰 확률·입찰자 수를 낙찰가와 같은 순간에 봉인, 근거 없으면 미산출, **확률은 적중률이 아니라 보정으로 채점**, 취소(0012)는 확률 해소에서 제외, 이중 집계 0 |
| `source-axis` | **다중 소스(AIOS) 껍데기** — 소스 축이 존재하고 준비 중 시장을 숨기지 않음·모든 카드에 소스 배지·**소스에 판단 신호 색 미사용**·소스가 봉인→채점→성적표까지 전파·공용 CSS 로드 순서와 중복 제거 |
| `manifesto` | **헌장이 사실인가** — Appendix A/B 인벤토리·스키마가 실제 파일·크론과 일치, GR12 존재, 낡은 수치 미포함 |

## `manifesto.test.js`가 일부러 깨지는 경우

함수·lib·테스트·페이지를 **추가하면 이 테스트가 실패합니다.** 버그가 아니라 의도된
트립와이어입니다 — 헌장 Appendix A(인벤토리)는 사실 기술이므로, 코드가 늘었는데 문서가
그대로면 헌장이 거짓말을 하게 됩니다. 실패 메시지에 실제 값이 찍히니 그 값으로 헌장을
고치면 됩니다.

## 아직 덮지 못한 것 (정직하게)

- **클라이언트 HTML 페이지** — 렌더 검증은 브라우저가 필요한데, Playwright를 devDependency로
  들이면 "의존성 0"이 깨진다. 그래서 스위트 밖에서 **환경에 이미 있는 Chromium**으로 돌린다.

  표준 절차(2026-07-30 정립 — 두 번 돌려 유효 확인):
  1. `python3 -m http.server 8799` (file://은 fetch가 막혀 반드시 http로 띄운다)
  2. `scoreboard`를 **두 가지 모양**으로 목킹해 각각 렌더 → `document.body.innerText`에서
     `null` / `undefined` / `NaN` 을 찾고, `pageerror`를 센다.
     - **빈 상태**: 모든 집계 필드 null (배포 직후·채점 전)
     - **부분 데이터**: 값과 null이 섞인 **실제 프로덕션 모양**
       (실측 예: `byAsset.부동산 = {n:1, hitRate:100, avgAbsErrPct:null}`)
       ← 빈 상태만 보면 이 경우를 놓친다. 헌장 GR6("null%" 금지)가 걸리는 자리가 여기다.
  3. 나머지 서버리스 함수는 전부 `abort` — 함수 미배포 상황에서 degrade가 도는지 함께 본다.

  대상은 scoreboard를 소비하는 `bidcast.html` · `bidcast-lab.html` · `bidcast-my.html`.
  새 지표·새 chronicle 종류를 추가하면 이 절차를 다시 돌릴 것.
- **실 외부 API** — 이 개발환경은 프로덕션 도메인으로 나가는 egress가 막혀 있어 라이브 호출을
  검증할 수 없다. fixture는 **실제 응답 구조를 그대로 재현한 것**을 쓰되(내 가정대로 만든
  목킹이 rtms-svc 파서 버그를 놓친 전례가 있다), 라이브 확인은 배포 후 창업자 몫으로 남는다.
- `agents.js`·`doc-extract.js`의 LLM 경로 — 생성 품질은 fixture로 판정할 수 없다.
  프롬프트 규율(면책 부착·"기재 없음" 강제)만 코드 리뷰로 확인한다.
